What this proves

The browser agent is a port of agent/dialogue.py + agent/tools.py + agent/store.py from this repo: the same slot-filling (service → date → time → name/phone), the same availability check (30-minute steps inside opening hours), the same overlap rule that rejects double-bookings, and the same booking codes (BRI-000001 for the first Bright Smile booking). Try booking the same slot twice — the second attempt is refused and the calendar keeps one entry. The same call run through the Python simulator gives the same record:

python -m agent.simulate --config configs/clinic.yaml \
    --script sample_data/call1_book.txt --today 2027-01-10
# BRI-000001: Cleaning with Dr. Amina Khan on 2027-01-15 10:00–10:45 (Ayesha Khan, booked)

Maya can also answer hours, services and prices, directions and FAQs, take a message, cancel by reference code, and reschedule. The voice worker (agent/worker.py) uses the same tools over a real LiveKit call.

Honest note about phone numbers: the framework, the demo and browser calls are 100% free. A real phone number that customers can dial from their mobiles is not free — the number and per-minute telephony are the client's paid add-on (LiveKit sells US numbers from about $1/month; Twilio/Telnyx are alternatives). The pipeline is built so the number is a configuration detail, not a rebuild.
